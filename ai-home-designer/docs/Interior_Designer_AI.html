Section 01 · Product Concept & Repository Footprint

Strict V1 Scope Turns Existing AI APIs into a Ship-Ready Mobile Product

Rather than training proprietary vision models or provisioning GPU clusters, Home AI orchestrates managed cloud primitives around a single high-value user loop: snap a room, pick a style, compare before and after, and share or upscale.

Core V1 User Journey

According to the project specification and masterclass walkthrough, V1 intentionally excludes paywall billing complexity and multi-theme toggles (shipping Dark Mode first) to validate demand quickly:

  1. Authenticate & Allocate Quota: Sign in via Email/Password, Google OAuth, or Apple Sign-In; receive 5 daily generation credits tracked in Postgres.
  2. Capture or Select Photo: Shoot a bedroom, kitchen, living room, or empty room using device camera or pick from media library.
  3. Select Style & Trigger Redesign: Pick from 8 styles (e.g., Luxury, Minimalist) and dispatch the room URL to the server proxy.
  4. Inspect Before/After Slider: View the redesigned room preserving exact walls and ceiling geometry via an interactive comparison slider.
  5. History, HD Upscale & Watermarked Share: Browse saved designs with blurred placeholders, upscale to HD on demand, or share with an automatic logo overlay.

Section 05 · Relational Data Model & Store Governance

Neon Postgres Schema, Better Auth & Mandatory App Store Controls

Managed via Drizzle ORM (drizzle.config.ts) and @neondatabase/serverless (neon.ts), the database separates authentication state from room design history and enforces Apple App Store compliance rules.

user

Core account identity, verification flag, and daily quota balance.
  • id (PK) · name · email
  • emailVerified (boolean)
  • image (OAuth avatar URL)
  • credits / daily quota (5/day)

account

Links Better Auth credentials and social OAuth providers.
  • id (PK) · userId (FK → user)
  • providerId (email, google, apple)
  • accountId · passwordHash
  • accessToken · refreshToken

session

Active authenticated mobile sessions and expiration tokens.
  • id (PK) · userId (FK → user)
  • token (unique session key)
  • expiresAt · ipAddress
  • userAgent

verification

One-time verification and password reset tokens (via Resend).
  • id (PK) · identifier
  • value (token / 6-digit code)
  • expiresAt

designs

Room transformation history referencing ImageKit URLs only.
  • id (PK) · userId (FK → user)
  • originalImageUrl (ImageKit)
  • generatedImageUrl (ImageKit)
  • roomType · style · createdAt

Section 07 · Iterative Build & Verification Loop

Eight-Phase Agentic Development & CodeRabbit QA Cycle

Features are built one at a time, checked manually in the simulator, audited by CodeRabbit on GitHub Pull Requests, and verified across cloud iOS/Android simulators via Expo Simulators.

Phase 01 · Plan Mode

Structured Co-Founder Interview

Switch Claude from Auto to Plan Mode. Run 4 batches of 3–6 questions covering stack, auth, quotas, and V1 scope; freeze decisions into PLAN.md.

Phase 02 · Local Setup

Expo Boilerplate & Tunnel

Install Node.js and VS Code. Scaffold with npx create-expo-app@latest and preview live via iOS Simulator, Android Emulator, or Expo Go QR.

Phase 03 · UI Reference

Mock-Data UI from Pinterest

Attach Pinterest reference screenshots + PLAN.md. Build all screens with mock data first (~83 changed files); refine typography and slider behavior one change at a time.

Phase 04 · Feature PRs

CodeRabbit Security Governance

Push feature branches to GitHub. CodeRabbit audits 10k–20k line PR diffs for XSS, CSRF, unescaped email HTML, and logic bugs, issuing a unified fix prompt for Claude.

Phase 05 · Backend Stack

Neon, ImageKit, OpenAI & Resend

Replace hardcoded mocks with real Postgres tables, Better Auth (Email, Google, Apple), ImageKit uploads, OpenAI dall-e-3 calls, and Resend email keys.

Phase 06 · Store Polish

Compliance & Media Polish

Add Profile settings, notifications, mandatory Delete Account cascade, Apple Sign-In parity, ImageKit w-400/q-80/f-auto thumbnails, watermarks, and HD upscaling.

Phase 07 · Legal & Web

Audited Legal Pages on Cloudflare

Capture framed mockups via shots.so, build legal/ landing + Privacy Policy + Terms via 3-stage code audit, and deploy via Wrangler CLI.

Phase 08 · Cloud QA & EAS

Expo Simulators & TestFlight

Run parallel cloud sessions (eas simulator --platform ios) for Agentic CI, attach screenshots/recordings to PRs, and ship with EAS Build / npx testflight.

Section 09 · Credentials & Production Implementation

          
Environment Secrets (.env.example vs .env.local) & Integration Code

          

            .env.example documents required keys without values and is committed to Git; .env.local stores live secrets locally and is excluded in .gitignore. Only EXPO_PUBLIC_* variables ship inside the mobile client bundle.
          

        


        

          

            .env.example / .env.local Template
            
          

          
# Neon Postgres Database Connection (Server-Only)
DATABASE_URL="YOUR_NEON_DATABASE_URL_HERE"

# OpenAI API Engine (Server-Only)
OPENAI_API_KEY="YOUR_OPENAI_API_KEY_HERE"

# ImageKit Developer Credentials (Private Key requires 6-digit email verification)
EXPO_PUBLIC_IMAGEKIT_PUBLIC_KEY="YOUR_IMAGEKIT_PUBLIC_KEY_HERE"
EXPO_PUBLIC_IMAGEKIT_URL_ENDPOINT="YOUR_IMAGEKIT_URL_ENDPOINT_HERE"

              neon.ts & drizzle.config.ts
              
            

            
// neon.ts
import { neon } from '@neondatabase/serverless';
import { drizzle } from 'drizzle-orm/neon-http';

if (!process.env.DATABASE_URL) {
  throw new Error('DATABASE_URL environment variable is missing');
}

const sql = neon(process.env.DATABASE_URL);
export const db = drizzle(sql);

// drizzle.config.ts
import { defineConfig } from 'drizzle-kit';

export default defineConfig({
  schema: './src/db/schema.ts',
  out: './drizzle',
  dialect: 'postgresql',
  dbCredentials: {
    url: process.env.DATABASE_URL!,
  },
});

          


          

            

              imagekit.ts (Transforms & Watermarks)
              
            

            
import ImageKit from 'imagekit-javascript';

const imagekit = new ImageKit({
  publicKey: process.env.EXPO_PUBLIC_IMAGEKIT_PUBLIC_KEY!,
  urlEndpoint: process.env.EXPO_PUBLIC_IMAGEKIT_URL_ENDPOINT!,
});

export const getThumbnailUrl = (imagePath: string): string => {
  return imagekit.url({
    path: imagePath,
    transformation: [
      {
        width: '400',
        quality: '80',
        format: 'auto',
      },
    ],
  });
};

export const getWatermarkedShareUrl = (imagePath: string): string => {
  return imagekit.url({
    path: imagePath,
    transformation: [
      {
        overlayImage: 'logo_watermark.png',
        overlayWidth: '150',
        overlayFocus: 'southeast',
      },
    ],
  });
};

          

        


        

          

            

              openai.ts (Server Redesign Engine)
              
            

            
import OpenAI from 'openai';

const openai = new OpenAI({
  apiKey: process.env.OPENAI_API_KEY,
});

export async function generateRoomRedesign(originalImageUrl: string, style: string) {
  const prompt = `Professional interior redesign of the provided room in ${style} style, photorealistic 8k resolution, maintaining exact architecture walls and ceiling structure.`;

  const response = await openai.images.generate({
    model: 'dall-e-3',
    prompt: prompt,
    n: 1,
    size: '1024x1024',
    quality: 'standard',
  });

  return response.data[0].url;
}
